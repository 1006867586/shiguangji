# 「可互动美食打卡地图」技术方案

> 项目：飨刻（shiguangji）Web 端（main 分支，Next.js + Supabase）
> 关联分析：`docs/map-creator-分析报告.md`（外部项目 Hatari130/map-creator 复用评估）
> 日期：2026-08-19 · 版本：v1.0（草案）

---

## 1. 背景与目标

### 1.1 背景
- 产品已有「聚餐即打卡」语义：参与聚餐（activities 报名）即算一次打卡/一顿，并接入积分与成就体系（016/017 迁移）。
- 现有地点能力是**离线/外链式**的：收藏夹（favorite_places，无坐标）、POI 匹配（lib/poi：高德 v5 + 百度，服务端密钥）、地图跳转（MapLauncher 唤起高德/百度 App）。
- **Web 端目前没有页内交互地图**。本次引入「可互动美食打卡地图」：用户在页内浏览打卡点、搜索/选点、打卡、查看足迹与圈子打卡分布。

### 1.2 目标（按里程碑）
| 里程碑 | 目标 |
| --- | --- |
| M1 一期 | 打卡点主档 + 打卡记录落库；页内地图浏览（标记/聚合/弹窗）；搜地点/选点打卡、撤销；「我的足迹」；活动详情页打卡入口 |
| M2 二期 | 圈子打卡地图（聚合视图，不泄露个人）；数据量增长后的后端网格聚合；成就体系联动（足迹城市数等新成就） |
| M3 三期 | GPT Image 生成「我的打卡地图」分享海报；小程序端地图能力评估 |

### 1.3 非目标（一期）
- 不做实时多人协作打卡、不做地图社交流、不做商家侧管理后台。
- 不引入 OSM/Google/Mapbox 等不合规底图（见第 9 节合规红线）。

## 2. 现状盘点（已具备的资产）

| 资产 | 位置 | 说明 | 复用方式 |
| --- | --- | --- | --- |
| POI 检索（高德 v5 / 百度 v2） | `lib/poi/providers.ts` | 服务端密钥（AMAP_KEY / BAIDU_MAP_AK），统一 `PoiCandidate`（GCJ-02 / BD-09） | 地点搜索直接复用；`/api/places/match-poi` 已暴露 |
| 坐标转换 | `lib/poi/coords.ts` | BD-09 → GCJ-02 纯函数 | 百度候选落库前统一到 GCJ-02 |
| 收藏夹 | `favorite_places`（005/007/008） | 用户店铺收藏，RLS 私有，**无坐标列** | 打卡可一键从收藏夹选点（需补坐标，见 5.4） |
| 聚餐/圈子链路 | `activities.group_id` | 活动必属于圈子 | 圈子地图 = 关联活动的打卡聚合 |
| 成就/积分 | 016/017 | recalc_gamification + 触发器 | 二期扩展新成就 |
| API 约定 | AGENTS.md | `{ data }` / `{ error }` 信封 | 全部新接口遵循 |

**结论：POI 检索与坐标体系无需新造，缺的是「页内地图渲染」+「打卡数据模型」两块。**

## 3. 总体架构与技术选型

### 3.1 架构总览

```
┌────────────────────────── Web 端（Next.js App Router, main 分支）──────────────────────────┐
│  页面：app/(main)/map  ·  我的足迹  ·  圈子 tab  ·  活动详情打卡入口                             │
│  组件：AmapMap（地图容器）→ CheckinMapView（标记/聚合/弹窗）→ CheckinSheet（打卡表单）           │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ REST（{data}/{error} 信封，Supabase cookie 会话鉴权）
┌───────────────▼──────────────────────────────────────────────────────────────┐
│  API Routes（app/api/map/*）                                                    │
│  places(城市列表/聚合) · checkins(打卡/撤销/我的足迹) · groups/[id]/map(圈子聚合)  │
└───────────────┬──────────────────────────────┬───────────────────────────────┘
                │                               │ 服务端密钥（不落前端）
┌───────────────▼──────────────┐   ┌────────────▼──────────────────────────────┐
│ Supabase                     │   │ 高德 Web 服务 API（lib/poi 现有）             │
│ places / checkins + RLS      │   │ 百度（备用 provider）                        │
│ RPC: get_group_checkin_places│   │ 高德 JS API 2.0（浏览器端地图，Referer 白名单）│
└──────────────────────────────┘   └───────────────────────────────────────────┘
```

### 3.2 地图渲染选型

| 方案 | 合规 | 与现有资产契合度 | 备注 |
| --- | --- | --- | --- |
| **高德 JS API 2.0（推荐）** | ✅ 白名单 | 高：AMAP_KEY 已在用、lib/poi 同源 GCJ-02、官方 MarkerClusterer 成熟 | 需单独申请 **Web 端 JS Key**（与 Web 服务 key 不同）+ 域名白名单；本地联调配 IP 白名单 |
| 腾讯位置服务 GL JS | ✅ 白名单 | 中：需新申请 key；POI 搜索需在 providers 增加腾讯 provider | WebGL 性能好；作为备选，切换成本低 |
| OSM / Mapbox / Google | ❌ 禁止 | — | 不合规，明确排除 |

**决策：M1 采用高德 JS API 2.0**（复用资产最大化，全链路统一 GCJ-02）。若后续选腾讯 GL JS，`lib/poi/providers.ts` 增加一个 provider 即可，业务层无感。

### 3.3 坐标体系
- 全链路 **GCJ-02**：高德候选原生 GCJ-02；百度候选经 `bd09ToGcj02` 转 GCJ-02；落库即 GCJ-02；前端 SDK 直接用。
- 不需要 WGS84（map-creator 的双坐标是为 OSM 准备的，本项目不用 OSM）。

## 4. 数据模型设计（迁移 018）

> 迁移文件：`supabase/migrations/018_food_checkin_map.sql`（编号紧跟 017）
> 完整 DDL 见附录 A。

### 4.1 `places` —— 打卡地点主档（共享 POI 注册表）
```text
id            uuid PK
name          text        -- 店名
address       text
city / district  text     -- 城市/区县（地图按城市筛选）
category      text        -- 品类：咖啡/餐厅/酒吧/甜品…
lng / lat     numeric(10,6)  -- GCJ-02
source        text        -- amap | baidu | tencent | manual
poi_id        text        -- 来源平台 POI ID（去重锚）
created_by    uuid → profiles
status        text        -- approved | pending_review | rejected（借鉴 map-creator needs_review）
created_at    timestamptz
```
- **去重**：`unique(source, poi_id) where poi_id is not null` + `unique(lower(name), city, lng, lat)`。
- **RLS**：approved 对登录用户公开可读；登录用户可贡献写入。
- **索引**：`(city, category)`、`(lng, lat)`。

### 4.2 `checkins` —— 打卡记录（个人私密）
```text
id            uuid PK
user_id       uuid → profiles（级联删）
place_id      uuid → places（级联删）
activity_id   uuid → activities（可空，set null）-- 关联聚餐
note          text
checked_at    timestamptz   -- 默认 now()
created_at    timestamptz
```
- **RLS：仅本人可读写**（PIPL：个人打卡坐标私有）。
- **索引**：`(user_id, checked_at desc)`、`(place_id)`、`(activity_id) where activity_id is not null`。

### 4.3 圈子维度推导（不新增字段）
圈子打卡聚合 = `checkins → activities.group_id` 分组统计。**不单独存 group 字段**，避免冗余与一致性问题。

### 4.4 与收藏夹衔接
`favorite_places` 增加坐标列（单独小迁移 019，或并进 018）：
```sql
alter table public.favorite_places add column if not exists lng numeric(10,6),
  add column if not exists lat numeric(10,6), add column if not exists city text;
```
收藏夹卡片「去打卡」时：未补坐标 → 先调 `/api/places/match-poi` 补坐标再打卡。

## 5. 后端 API 设计

> 全部遵循 `{ data }` / `{ error }` 信封；鉴权走现有 Supabase cookie 会话。

| 接口 | 方法 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| `/api/map/places?city=&category=&exclude_checked=` | GET | 城市打卡点列表（approved），附 `i_checked`（本人是否已打卡） | 登录 |
| `/api/map/checkins` | POST | 打卡：body `{ place:{name,address,city,district,category,lng,lat,source?,poi_id?}, activity_id?, note? }`；先 upsert place 再插 checkin；若带 activity_id 校验用户是该圈子成员 | 登录 |
| `/api/map/checkins/me?cursor=` | GET | 我的足迹分页（含 place 摘要 + activity 摘要），`next_cursor` 翻页（沿用 request.ts 的 raw 约定） | 登录 |
| `/api/map/checkins/[id]` | DELETE | 撤销打卡（本人） | 登录 |
| `/api/groups/[id]/map` | GET | 圈子打卡聚合 → 调 RPC `get_group_checkin_places`（仅返回 place + 计数 + 最近打卡时间，**不返回打卡人**） | 圈内成员 |
| `/api/places/match-poi`（现有） | GET | 地点搜索（高德/百度） | 复用 |

**关键实现要点**
- 打卡接口事务：`upsert place（按去重键）→ insert checkin`，用 Postgres RPC（`insert_checkin(...)` security definer）保证原子性 + RLS 一致，或 API 层顺序执行并捕获唯一键冲突回查。
- 圈子聚合 RPC：security definer + **成员校验**（非成员直接拒绝），聚合结果脱敏（无 user_id）。

1. **聚餐即打卡贯通**：活动详情页打卡时带 `activity_id` → 该打卡同时计入成就的「顿数/连续打卡」口径（016 已有 attendance 统计，两者并行、互不冲突；地图打卡是显式动作，attendance 是报名语义，一期不合并）。

3. **通知（可选）**：圈子内有人打卡不推通知（避免打扰）；仅打卡获得新成就时复用现有通知中心。

## 9. 合规与安全红线

1. **地图源**：仅允许 高德 / 腾讯地图 / 百度 / 天地图；**禁止** OSM 直连、Google、Mapbox、Leaflet+OSM 等无资质底图。本项目选高德 JS API 2.0。
2. **坐标系**：全链路 GCJ-02。
3. **密钥安全**：
   - Web 服务 key（AMAP_KEY 等）只存在于服务端 `.env.local`，前端不可见（现有 lib/poi 已如此）。
   - Web 端 JS Key 用于浏览器：高德控制台配置 **域名白名单**（正式环境用已备案域名）；本地联调配 IP 白名单；禁止把 key 提交进仓库。
4. **个人位置数据（PIPL）**：
   - `checkins` 仅本人可读（RLS），不做公开展示。
   - 圈子聚合只输出「地点 + 计数」，**不暴露打卡人身份与精确打卡时间**（security definer RPC + 成员校验）。
   - 收藏夹/打卡数据导出与删除遵循账号删除链路（现有 profiles 级联已覆盖）。
5. **审查**：地图展示内容不涉及敏感点位标记；不采集非本人坐标。

## 附录 A：迁移 018 核心 DDL（草案）

```sql
-- places 打卡地点主档
create table if not exists public.places (
  id uuid default uuid_generate_v4() primary key,
  name text not null,
  address text,
  city text,
  district text,
  category text,
  lng numeric(10,6) not null,
  lat numeric(10,6) not null,
  source text not null default 'manual' check (source in ('amap','baidu','tencent','manual')),
  poi_id text,
  created_by uuid references public.profiles on delete set null,
  status text not null default 'approved' check (status in ('approved','pending_review','rejected')),
  created_at timestamptz not null default now()
);
create unique index if not exists uq_places_source_poi on public.places(source, poi_id) where poi_id is not null;
create unique index if not exists uq_places_name_city_lng_lat on public.places(lower(trim(name)), city, lng, lat);
create index if not exists idx_places_city_category on public.places(city, category);
create index if not exists idx_places_lng_lat on public.places(lng, lat);

-- checkins 打卡记录
create table if not exists public.checkins (
  id uuid default uuid_generate_v4() primary key,
  user_id uuid references public.profiles on delete cascade not null,
  place_id uuid references public.places on delete cascade not null,
  activity_id uuid references public.activities on delete set null,
  note text,
  checked_at timestamptz not null default now(),
  created_at timestamptz not null default now()
);
create index if not exists idx_checkins_user on public.checkins(user_id, checked_at desc);
create index if not exists idx_checkins_place on public.checkins(place_id);
create index if not exists idx_checkins_activity on public.checkins(activity_id) where activity_id is not null;

-- RLS
alter table public.places enable row level security;
alter table public.checkins enable row level security;
create policy "places select approved" on public.places for select using (status = 'approved');
create policy "places insert logged in" on public.places for insert with check (auth.uid() is not null);
create policy "checkins select own" on public.checkins for select using (user_id = auth.uid());
create policy "checkins insert own" on public.checkins for insert with check (user_id = auth.uid());
create policy "checkins update own" on public.checkins for update using (user_id = auth.uid());
create policy "checkins delete own" on public.checkins for delete using (user_id = auth.uid());

-- 圈子打卡聚合（脱敏，成员可见）
create or replace function public.get_group_checkin_places(p_group_id uuid)
returns table (place_id uuid, name text, address text, category text, lng numeric, lat numeric, checkin_count bigint, last_checked_at timestamptz)
language plpgsql security definer set search_path = public as $$
begin
  if not exists (
    select 1 from public.group_members gm
    where gm.group_id = p_group_id and gm.user_id = auth.uid()
  ) then
    raise exception 'not a member';
  end if;
  return query
    select p.id, p.name, p.address, p.category, p.lng, p.lat,
           count(c.id)::bigint, max(c.checked_at)
    from public.checkins c
    join public.activities a on a.id = c.activity_id
    join public.places p on p.id = c.place_id
    where a.group_id = p_group_id
    group by p.id
    order by count(c.id) desc, max(c.checked_at) desc nulls last;
end; $$;
```
